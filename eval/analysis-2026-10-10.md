# Alidade 评测分析报告（2026-10-10）

对比对象：**改造前**（Data Formulator 原版代码，仓库第一个提交）与**改造后**（当前 Alidade）。
模型：两边都是 `deepseek-flash`，同一套题、同一套判分规则。原始结果在 `eval/results/` 下。

> **更正（2026-10-11）：** 本报告评测时，系统提示词里的几个示例和评测题直接对应：
> "most successful"、"performance"、"last year"（对应 3 道"必须先澄清"题里的"最成功""表现""去年和今年"），
> "removed 87 duplicate orders"（87 正是脏销售表的重复订单数），以及 "return, volatility, trading volume"。
> 因此下面"必须先澄清的题 17% → 83%""数据清洗 80% → 100%"等数字**可能偏高**，引用前需要重跑。
> 这些示例已在 2026-10-11 换成和评测无关的内容，并加了测试（`tests/backend/agents/test_prompt_eval_separation.py`）防止再次发生。
> 用干净提示词重测的结果见 [analysis-2026-10-11.md](analysis-2026-10-11.md)，引用时以那一份为准。

## 结论

1. **先澄清再动手有效。** 遇到宽泛问题或涉及投资建议时，改造后在出图前先反问的比例从 6% 升到 81%，必须先澄清的题完成率从 17% 升到 83%。
2. **猜错方向时白花的成本减半。** 模糊/需澄清题在用户确认方向之前平均消耗的 token 从 84,425 降到 43,106（−49%）。
3. **数据体检修好了旧版答错的脏数据题。** 数据清洗题成功率从 80% 升到 100%。唯一的差别是平均订单金额题：旧版没发现 87 条重复订单，两次都答错；新版两次都先去重再计算。
4. **代价：总 token 和耗时略有增加。** 模糊题平均总 token 多 13%，平均耗时多 11%。总 token 不降，是因为评测时用户总是选推荐选项，Agent 确认方向后仍然要把分析做完。
5. **图表自检在这两轮里没有触发过。** 两个版本最终展示的图表都没有阻断性问题，所以这次的数据既不能证明、也不能否定这项功能的价值。

## 1. 被评测的改动

| 改动 | 位置 | 作用 |
|---|---|---|
| 先澄清再动手 | `analyst/engine/prompts.py`、`planning.py`、`skills/core/SKILL.md` | 宽泛问题、标准不明确的问题、投资建议类问题，在任何图表和计划之前先用 `ask_user` 给 2–3 个带推荐的选项；不给买卖建议 |
| 数据体检 | `agents/data_quality.py`、`agents/context.py` | 每张表放进上下文时，用 pandas 扫一遍整张表（不调模型），把重复行、文本形式的数字和日期（含多种日期格式混用）、同一取值的大小写/空格变体、缺失值写成几行提示，附上修法 |
| 折线图线数规则 | `analyst/engine/chart_check.py` | 超过 10 条线给警告，超过 20 条拦下来要求改图 |
| 评测指标 | `eval/run_eval.py`、`eval/report.py` | 新增缓存命中、未命中缓存的输入 token、用户确认方向前的 token |

## 2. 评测方法

- **题目**：41 道题，8 类（查询、趋势、多步、陷阱、模糊、数据清洗、多表关联、必须先澄清），见 `eval/questions.yaml`。
  - 数据清洗题用 `eval/data/make_data.py` 生成的脏数据，**不清洗就会得到另一个答案**；
  - 必须先澄清的题要求在出任何图之前先反问，出了图再问也算失败。
- **运行**：每题一个子进程、一个全新工作区，直接调用 Agent；每题跑 2 次。
- **反问的回答**：自动选第一个（推荐的）选项。
- **判分**：
  - 结论里出现标准答案（`mentions_any` / `mentions_all`）；
  - 数值题落在误差范围内（`answer_number`）；
  - 该出图的题出了图；
  - `expect_ask` 题在出图前先反问。
- **token**：包装 `litellm.completion` 统计，缓存命中数取服务商返回的 usage。

## 4. 逐项分析

### 4.1 数据体检

在平均订单金额题（`clean-sales-avg`，正确答案 $511.54）上：

| 版本 | 两次的答案 | 做法 |
|---|---|---|
| 改造前 | $510.63、$510.63 | 去掉了 `$`、逗号和 N/A，但没去重：用 602 行中的 548 笔有效订单计算 |
| 改造后 | $511.54、$511.54 | "删除 87 条完全重复的记录（602 → 515 行）；50 条空值 / N/A 按缺失处理而不是按 0 计"，用 465 笔有效订单计算 |

改造后的结论里会主动说明怎么处理的，这正是核心技能说明里要求的。

上一轮全量评测（还没有数据体检时）两个版本都没过这道题，说明这是模型本身的盲区，不是偶然失误：它会清洗格式，但不会主动检查重复行。数据体检把"整张表才看得出的问题"在开局就交给模型，做法和 Meta-Harness 论文在终端任务上发现的"环境预热"思路一致。

体检只在表确实有问题时才加提示：自带的股票数据零提示，ISO 格式的文本日期也不提示，避免占用上下文。

### 4.2 先澄清再动手

- 旧版遇到"哪只股票去年和今年表现差别大""哪部电影最成功"这类题，大多直接挑一个口径开始画图，平均画 2.8 张；
- 新版只看一次数据就给出口径选项（例如"按自然年 / 累计收益率""全球票房 / 回报率 / 口碑"），用户选完再做。

新版唯一没过的一次是 `clarify-stocks-period#2`：模型没反问，直接按自然年算了。只出现一次，不针对它单独调提示词，以免对这道题过拟合。

**为什么总 token 不降，而"确认方向前的 token"减半：** 评测脚本总选推荐选项，确认后的分析量和旧版差不多，再加上多了一轮问答，所以总量略增。真正省下的，是方向猜错时白花的那部分：旧版在用户有机会表态之前就花掉约 8.4 万 token，新版约 4.3 万。

### 4.3 token 与成本

- **前缀是稳定的。** 同一次运行里每次调用只在末尾追加消息，系统提示和工具列表在不同题之间完全相同，所以缓存命中率很高（94% / 97%）。
- **"平均输入 token"会高估成本。** 按 DeepSeek 的计费方式，命中缓存的输入远比未命中便宜。改造后未命中缓存的输入 token 少了 37%，实际输入成本的差距比"平均输入 token +8%"看起来小。具体金额取决于服务商当时的价格，这里没有换算。

### 4.4 图表检查

两轮评测里自检触发次数都是 0，最终图表的阻断错误率两边都是 0%。新加的折线图规则在全量评测里给了 4% 的图表警告，两个版本比例相同。要验证自检本身的价值，需要补几道"容易画错"的题（几十个类别的折线图、几千行没聚合的数据等）。

## 5. 局限

- **样本小。** 重点三类题每个版本 26 次运行，必须先澄清的题只有 6 次（83% 即 5/6）。旧版的反问比例两轮分别是 19% 和 31%，说明随机波动不小，差距在几个百分点以内的指标不要下结论。
- **只用了一个模型。** 结论是否适用于其他模型（如 qwen-plus），需要另跑。
- **反问的回答是自动的。** 总选推荐选项，测不出"用户其实想要另一个方向"时谁更好。
- **判分是关键词和数值匹配。** 可能漏判，已结合 LLM 评分和 `logs/` 原文抽查。
- **题目是自己出的**，也在这些题上调过提示词，存在一定的过拟合风险。更可靠的做法是留一部分题只用于最终检验。

## 6. 简历可用的表述

> 为数据分析 Agent 设计"澄清优先"流程和数据体检。在 13 道难题（每个版本 26 次运行）上：出图前先澄清的比例从 6% 提升到 81%，用户确认方向前的 token 消耗降低 49%，数据清洗题正确率从 80% 提升到 100%。另搭建了评测框架（41 道题、8 类，新旧版本自动对比）。

引用时注明模型和样本量，并区分"重点三类题"和"全部 41 道题"两组数字。

## 7. 下一步

1. **结论数字核对：** 结论里的数字必须能在本次运行实际算出的结果里找到，防止编数字。
2. **一次回复调多个只读工具：** 减少 LLM 来回次数，针对耗时 +11%～17% 的问题；同时删掉提示词里过时的 `delegate`。
3. **模拟用户评测：** 给澄清题设隐藏意图，由一个 LLM 按意图回答反问，衡量"先问"是否真的让结论更贴合用户想要的方向。
4. **补容易画错的图表题**，验证图表自检。
5. **扩大样本：** 每题跑 3 次，再换一个模型跑一遍；留出一部分题只用于最终检验。

## 复现

```powershell
# 重点三类题
.\eval\eval.ps1 new -Only ambiguous,clarify,cleaning -Tag focus
.\eval\eval.ps1 old -Only ambiguous,clarify,cleaning -Tag focus
.\eval\eval.ps1 compare -Tag focus

# 全部题目
.\eval\eval.ps1 all
```

旧的结果目录可以直接用 `python eval/report.py <目录>` 按最新的判分规则重新汇总。
